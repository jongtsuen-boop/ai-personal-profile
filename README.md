## 待辦事項追蹤

使用本儲存庫的 [Issues](../../issues) 追蹤個人檔案的補充與更新：

1. 建立 Issue，寫清楚目標與完成條件；可使用「個人檔案更新待辦」範本。
2. 在內文使用 `- [ ]` 列出待辦事項。
3. 提交變更時引用 Issue 編號，例如 `docs: 更新溝通偏好 (#1)`。
4. 確認 README 已更新後，再關閉 Issue。

## 版本紀錄與還原

本儲存庫使用 Git 保存每次提交的版本。只有已提交（commit）的變更，才會納入版本紀錄。

- 在 GitHub 檔案頁面選擇 **History**，查看歷次變更。
- 每次提交都附上清楚的變更說明。
- 若要撤銷已推送的變更，使用 `git revert <提交SHA>` 建立還原提交，保留原有紀錄，再推送至遠端。
- 避免強制推送或改寫共用的版本歷史。

## 本機同步

第一次下載：

```bash
git clone https://github.com/jongtsuen-boop/ai-personal-profile.git
cd ai-personal-profile
```

每次修改前，先同步遠端變更：

```bash
git pull --ff-only
```

編輯後，提交並推送變更：

```bash
git add README.md
git commit -m "docs: 更新個人檔案"
git push
```

## 跨 AI 使用方式

將此儲存庫連結提供給其他 AI，並明確要求讀取最新的 README。若 AI 無法開啟連結，可直接貼上 README 內容。不同 AI 不會自動同步這份檔案；更新後，請讓 AI 重新讀取，或提供最新版本。範例與待填欄位不得視為真實的個人資料。
